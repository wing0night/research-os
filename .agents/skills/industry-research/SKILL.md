# Industry Research

从一个行业问题出发，主动发现资料、建立证据链并解释变化机制。默认中文，首次出现的术语和关键公式需解释；报告保存到当前工作区。

## 使用边界

- 适用于开放式行业探索，不要求先给链接。用户提供的材料作为检索种子，继续寻找独立来源与反例。
- 以论文技术比较、公式推导、训练技巧和实验设计为主要目标时，优先使用 literature-review-search；行业报告可以纳入论文，但还需检查实际应用证据。
- 匹配用户要求的深度和篇幅；不把“广泛”理解为穷尽互联网，也不为了凑数量收集无关材料。

## 研究范围与检索

1. 记录目标、输入、产出、验收标准、地区、时间窗口、读者用途和截止日期。未指定时声明合理假设；把“近年”转换成明确日期，不混用中国与全球的制度和市场口径。
2. 建立问题树：行业怎样运作、近年发生什么、技术如何使用、谁在采用、收益与成本、竞争与监管、未来机会及约束。优先解决用户的关键问题。
3. 建立来源地图与中英文关键词，搜索同义词、机构名、应用场景、失败案例和反方观点。先广搜，再围绕争议补证。记录实际执行的查询、日期、平台和筛选理由。
4. 对当前行业事实、监管、数字和前景依据进行联网核验。搜索摘要只用于找线索，关键论断必须打开来源；核对发布日期、事件日期、统计期间及版本。
5. 跟踪引用到原始报告/数据，合并转载、同一新闻稿和同一数据集衍生报道。单一消息源经多家转载仍算一条证据。
6. 关键问题获得可用证据、主要分歧已解释、连续两轮定向补搜无实质新发现时结束；若预算先耗尽或来源不可达，交付部分覆盖报告并注明缺口。不得声称全面覆盖。

## 按主张判断证据

| 来源 | 能支持什么 | 需要核查什么 |
|---|---|---|
| 官方统计、监管和交易所文件 | 指标定义、制度、正式发布的行业事实 | 地区、样本、修订、生效日与口径 |
| 企业披露、产品文档、招聘和技术博客 | 企业公开行动、产品能力或人才需求 | 自我宣传、选择性披露；招聘不能证明已部署 |
| 研报、咨询报告、行业调查 | 市场估计、框架、样本内观察 | 作者、资助、方法、样本和预测假设；多份报告可能共用数据 |
| 论文与技术资料 | 在给定条件下的方法和实验 | 同行评议/预印本、数据泄漏、复现、与生产条件的差距 |
| 媒体与具名访谈 | 事件线索、从业者经验 | 是否一手采访、引用上下文、个体代表性 |
| 社媒、论坛、播客 | 新线索、争议、经验和情绪 | 原帖、身份可验证性、时间、营销动机、幸存者及平台偏差 |

社媒可直接证明“某人公开表达了某观点”，通常不能单独证明该观点对应的行业事实。保存原帖链接或节目时间戳；二手截图、匿名爆料、无法访问原文的材料注明状态，不据此建立核心结论。平台不可访问时列出检索盲区，使用合法公开替代来源，不绕过登录或付费限制。

技术机制用原始论文/官方技术文档支持；媒体与社媒可支持采用情况和讨论热度，但不能替代技术验证。重要结论尽量用不同来源类型、不同数据来源交叉验证；正式法规等唯一权威来源无需机械凑两条。

## 综合分析

- 区分事实、机构自述、受访者观点、研究者推断和未来情景。证据强弱按具体主张评估，不把来源品牌或热度当可信度分数。
- 提取“问题—方法—采用阶段—收益证据—资源成本—局限”，既看产品功能，也看组织流程、数据、训练效率、运营和商业模式的变化。
- 区分概念演示、回测/离线实验、试点、生产部署和行业普及；不存在公开证据时写“不明”，不能推断成没有采用。
- 解释分歧的来源：时间、地区、样本、定义、利益立场或方法不同。不能平均相互冲突的数字来制造共识。
- 数字紧邻引用，记录单位、币种、名义/实际值、样本和期间；预测与实绩、总量与增速、相对百分比与百分点分开。
- 前景采用基准/乐观/承压情景，列驱动因素、反证、可观察指标、时间尺度及更新触发条件；不凭空分配概率或给确定性结论。
- 研究建议说明适用对象和证据边界，不能仅把“AI 很重要”作为结论。提出进一步访谈或实验不等于执行联系、购买或部署。

## 报告与归档

默认建立 `reports/YYYY-MM-DD-<topic-slug>/`，英文 slug；同日重名时追加 `-v2` 等，不覆盖历史记录。用户指定工作区内路径时优先遵循。先确认工作区根目录；写入失败时说明实际状态，不能只输出路径就称已保存。

交付三个互相链接的 Markdown 文件：

- `report.md`：研究元信息（目标、输入、产出、验收标准、范围与日期）、一页摘要、行业基础概念、近年变化、实践与案例、可迁移方法、争议与证据强弱、前景情景、用户相关启示、未验证项和下一步。
- `sources.md`：来源 ID、作者/机构、标题、URL、来源类型、发布日期/统计期间/访问日、证据位置、访问深度（全文/摘要/二手）、支持的主张、利益关联与限制；保留纳入理由及重要排除项。
- `search-log.md`：实际查询和渠道、覆盖地图、追溯/去重记录、未访问来源、停止原因。不得补造查询、访问或核验记录。

正文重要论断使用直接支持它的链接，并可链接来源 ID；不能仅在结尾堆参考文献。只保存必要摘录和原创归纳，不复制完整付费研报或含个人隐私的社媒材料。

交付前读回文件：核对主张与引用对应、时间口径、正文数字、社媒推断边界、内部链接和情景假设。验收标准是关键问题得到回答且证据可追溯，不是固定来源数量。说明哪些检查实际完成。

最后按 `Task / Result / Verification / Uncovered / Next step` 简短汇报并提供报告链接。写成报告不代表内容已经独立实证验证。
