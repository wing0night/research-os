# Literature Review Search

把一个研究问题整理成可追溯、可核验、深入浅出的文献调研综述。默认中文输出；论文题目、作者、期刊/会议、方法名和公式保留原文或标准英文记法。

## 任务边界

- 先确认综述问题、时间范围、领域边界、目标读者和期望深度；缺失时做最小合理假设，并在开头声明。
- 优先检索原始论文、官方项目页、正式出版版本和作者公开的补充材料；预印本、博客或二手解读只能作为线索或背景，不替代关键证据。
- 不把搜索摘要、标题或模型自述当作已验证事实。对重要结论打开并检查论文正文、图表、附录或实验设置。
- 区分“论文明确报告”“根据多篇论文归纳”“尚未验证/无法从公开材料判断”，不编造实验结果、引用、页码或 DOI。
- 如果无法联网或无法拿到全文，明确写出检索范围和证据缺口，不用记忆补齐细节。

## 工作流

1. **定义问题**：写出目标、输入、产出、验收标准；拆成方法、数据、训练/推理、评测、应用和局限等子问题。
2. **建立检索式**：为核心概念列同义词、缩写、旧称和易混淆词；组合宽搜、方法名搜、引用追踪和时间/领域过滤。记录查询式、数据库/网站、检索日期和筛选理由。
3. **筛选与去重**：先看标题/摘要，再核验正文；去除重复版本、明显不相关论文和无法确认来源的材料。保留“排除清单”及排除原因，避免选择性引用。
4. **制作证据表**：至少记录每篇文献的完整引用、研究问题、核心方法、数据/设置、基线、指标、主要结果、限制、证据位置和与综述问题的关系。
   同时执行下文“可迁移方法审查”，从方法、实现、消融、附录及复现说明中提取训练与工程经验，不能仅按输入输出功能给论文分类。
5. **综合而非罗列**：按问题或方法演进组织观点，比较共同点、差异、适用条件和冲突结果；不要把逐篇摘要简单拼接成综述。
6. **写作与核验**：先写读者能快速理解的结论地图，再补技术细节；逐项检查数字、术语、公式、引用和“谁证明了什么”。
7. **落盘交付**：将最终综述写入工作区根目录的 `literature/` 目录，使用 `YYYY-MM-DD-<topic-slug>.md` 命名；同主题的新调研新建带日期的文件，不覆盖历史记录。

## 工作区文档要求

- `literature/` 是文献调研综述的统一归档目录；目录不存在时创建它。
- Markdown 文件开头记录：主题、日期、目标、输入来源、检索范围、产出和状态。
- 正文必须保留检索式/来源、纳入与排除标准、证据边界、参考文献、未验证项和下一步。
- 链接使用稳定的论文、项目页、DOI 或官方文档 URL；不要只写搜索结果页或无法追溯的标题。
- 文件写入完成后重新读取并检查标题、引用链接、公式、`Uncovered`/`未验证项` 和 `Next step` 是否存在。
- 不删除旧综述，不把新的结果静默改写到旧文件；需要修正时追加日期和修正说明，保留原始事实。

## 面向初学者的表达要求

- 首次出现的专业名词写“中文名（English，缩写）”，用一句白话说明它解决什么问题；必要时补一个小例子或类比，但标明这是类比。
- 每个关键公式都解释：每个符号代表什么、输入输出是什么、直觉是什么、公式在论文中承担什么作用。不要只贴公式不解释。
- 区分目标函数、损失函数、评价指标、概率、期望、均值、方差、精度、召回率等容易混淆的概念；涉及假设时说明适用条件。
- 采用“先直觉，后定义，再细节”的顺序。复杂方法先用 3—5 句话讲清流程，再介绍模块和公式。
- 对图表给出读图方法：横纵轴、比较对象、越高/越低是否更好、误差线或显著性如何理解，以及图表不能说明什么。
- 保留必要技术深度，但避免未经解释的缩写、符号堆叠和“显然”“显著提升”等无证据措辞。

## 推荐输出结构

```text
# 文献调研综述：<主题>

## 0. 一页结论
- 研究问题是什么
- 当前主流路线有哪些
- 最可靠的共识、主要分歧和关键空白

## 1. 背景与基础概念
- 读者需要先知道的名词解释
- 最小必要公式：符号、直觉、作用和适用条件

## 2. 检索范围与方法
- 数据库/网站、检索日期、检索式
- 纳入/排除标准、版本去重、证据等级和未覆盖范围

## 3. 方法脉络与代表性工作
- 按方法类别或时间演进组织
- 每类的核心思想、代表论文、优缺点和适用场景

## 4. 横向比较
- 数据、模型/算法、训练或推理成本、指标、结果、限制
- 明确哪些数字可直接比较，哪些不能直接比较以及原因
- 可迁移方法表：原始瓶颈、机制、收益证据、代价、目标论文接口、迁移条件与最小对照

## 5. 争议、失败经验与开放问题

## 6. 对当前研究的启示
- 只提出有证据支持的建议；区分事实、归纳和推测

## 7. 术语与公式速查

## 8. 参考文献与证据索引

## 9. 未验证项与下一步
```

根据任务删减章节即可，但不能删掉检索范围、证据边界和未验证项。若用户指定格式（如 BibTeX、表格、Markdown、中文学位论文风格），优先遵循用户格式。

## 融合研究方案

多篇论文综述应包含“如何结合核心思想开展研究”。用户仅要求文献事实梳理时可省略；默认作为待验证提案，不能写成已有结果。

- 列出每篇工作的可借鉴思想、承担的模块、输入输出接口和兼容性缺口；区分思想借鉴、模型复用和实际可直接运行的组合。
- 分别考虑能力组合与方法迁移：例如把一篇论文的通信压缩、监督设计或训练课程用于另一篇论文，无需调用原模型。按瓶颈匹配程度排序；没有合适迁移点时解释原因，不强凑组合。
- 提炼一个主要科学问题、可证伪假设及创新性边界；未经相关工作检索，不宣称首次提出。
- 解释融合架构、数据流、训练目标与公式符号，指出监督信号如何取得，以及推理时是否可用。
- 给出分阶段实验：最小原型、基线、单变量消融、泛化测试，必要时再扩展到真实系统。各阶段记录输入、操作、产出、验收标准、证据与停止条件。
- 列出数据及标注、代码与权重、计算与存储、人员时间、可选设备；标明哪些已核验可用，哪些只是预算假设，先实测显存和吞吐再估算成本。
- 对齐训练数据量、计算预算与评测协议；明确随机种子、重复次数、置信区间、失败归因和数据泄漏控制。
- 最后给出可立即开展的首个实验、未验证项和替代方案；提出实验不等于获得下载权重、付费租卡或执行实机实验的授权。

## 可迁移方法审查

对每篇技术论文追问：“去掉任务名称和输出功能后，哪些设计仍有价值？”检查以下维度，未涉及或未读到时明确标记，不补造技巧：

- 架构与通信：全局/局部注意力、token 压缩、共享参数、预测头与中间激活。
- 监督与优化：从主输出推导辅助监督、损失尺度、梯度稳定性、初始化、冻结/微调、蒸馏与自监督。
- 数据与训练课程：质量筛选、伪标签、混合比例、分辨率和序列长度调度。
- 系统与评测：并行策略、缓存、精度、算子、复现协议与失败经验。

每个高价值技巧用一行或短卡片记录：原始瓶颈 → 具体机制 → 原文/代码位置及版本 → 原场景收益与代价 → 目标任务改动位置 → 必要假设 → 最小对照与否决条件。区分作者提出、沿用已有技术、作者经验性观察及综述者推断；未检索先例不能宣称原创。

成本必须区分参数/优化器状态显存、中间激活、FLOPs、吞吐、墙钟时间、GPU-hours、标注与预处理成本。标明训练或推理、硬件数与型号、分辨率、序列长度、batch、精度和测量边界；缺失项写未知。多项联合节省不得归因于单项，不得将显存节省率当成时间或费用节省率。

迁移前核对目标是否已有同类优化、真实瓶颈是否相同、预训练接口是否被破坏，以及额外重训/教师/解码成本。重点检查因果掩码、时间顺序、运动向量增强规则及辅助输出是否真的可由主输出确定。保留失败反例；“能减少计算”与“保持任务质量”分别验证。

效率研究至少设计同数据预算与同计算预算两组比较，记录达到预设质量所需的总 GPU-hours、峰值显存及质量变化。优先一个最小改动；通过单项消融后再组合。新增技巧必须改变研究建议或实验设计，不能只补一个术语清单。

## 证据与引用规则

- 关键事实后紧跟引用；引用应能支持该句具体内容，而不是只支持主题相关性。
- 结果数字必须同时给出任务、数据集/设置、指标和比较对象；不同设置下不要直接排排名次。
- 对综述性判断尽量提供多篇相互独立的来源；若只有单篇论文，写成“该论文报告”而不是领域共识。
- 参考文献至少包含作者、年份、题目、来源和稳定链接或 DOI（仅在已核验时填写）。
- 需要时维护一张“主张—证据”表：主张、来源、证据位置、证据类型、是否直接支持、备注。

## 最终检查

- 是否回答了原始研究问题，而不只是总结论文？
- 是否同时审查了功能贡献与可迁移训练/工程方法，并为高价值迁移点给出来源、成本口径、适用条件和反例？
- 是否让没有背景的读者理解关键术语、流程和公式？
- 是否把事实、综合判断、推测和未验证项分开？
- 是否保留检索式、筛选标准、纳入/排除理由和证据位置？
- 是否存在不可比实验被强行比较、引用与句子不匹配或无来源数字？
- 是否给出可执行的下一步，而不是泛泛地说“需要更多研究”？

除聊天回复外，必须交付一个工作区 Markdown 文件，并在回复中给出其路径。

完成后用以下短格式报告任务状态：

```text
Task: <综述主题与范围>
Result: <综述已覆盖内容与核心结论>
Verification: <检索来源、论文数量/类型、证据表或核验动作>
Uncovered: <未覆盖、全文不可得、不可比结果或未验证项>
Next step: <建议的后续检索、复核或实验>
```
